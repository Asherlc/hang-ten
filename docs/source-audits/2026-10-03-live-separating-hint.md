# Chronological separating-direction screen

A preceding query supplies a direction hint; every current query rechecks a
whole-segment support separation. The hint alone cannot omit a face. This differs
from the closed four-fixed-axis preflight: triangle support in the query-derived
direction is retained, with current endpoint support recomputed. First-use misses
and actual refresh work are counted. No product source changed.

The exhaustive query corpus records face masks, link indices and configuration
batch order from the original solver at steps139 and140. Its capture retained
all triangle arithmetic, and 493 persisted physics states/correction decisions
matched an independent original solver. The hints use only preceding queries;
training never uses the current query's future answer. Each proposed omission
was checked against the original source-derived point/link/merit witnesses and
finite clearance receipt, retaining all original work during coverage validation.

For the definitive exact-decoder run, 14,445 of 14,934 current face visits propose
separation; 489 refresh, zero first-use misses and zero ray blockers. Cold current
replay has 4,978 first-use misses and 5,304 refreshes. The larger original row radius
is used. The original tolerant ray branch is retained on proposed whole-face skips.
Seven alternating serial predecoded kernel clocks give median ratio **0.294123**,
passing the fixed necessary0.50 cost screen. Lookup, fresh support checks and
refresh are timed; earlier-state training and decoding are excluded. This is a
non-adoptable cost ceiling, not complete-step or parallel engine performance.

The whole-face envelope does not yet enclose every rounded barycentric result of
`triangleClosest`. A safer continuation retains original endpoint and ray kernels
for every face, and omits only the three edge kernels after an outward-rounded
interpolation support bound. Its final median ratio **0.957535** fails0.50.
**That edge-only variant is CLOSED; no tuning, trajectory or app adoption.**
Its source-level envelope was reviewed by Astra, conditional on optimized compiler
checks. Such checks were not pursued after the failed cost discriminator. The
faster whole-face ceiling remains a feasibility observation with an unresolved
proof requirement, not an accepted implementation.

The first build lacked unused chain-sweep dependencies and ran no simulation.
Two initial kernel runs used Foundation's numeric bridge, which can shift query
coordinates by one ULP. They are retained but superseded for captured-input
provenance. Fresh runs use the existing exact JSONDecoder adapter and the original
radius addition expression, preserving the threshold and workload. Both corrected
runs independently rechecked every proposal. No result was rounded to a pass.

All exact new compile/run groups were cleaned and independently verified absent;
the adjacent JSON lists each receipt and SHA-256 input/output bindings. No complete
step p95, trajectory equivalence, generic floating-point proof, device measurement
or new recording has been established.
