# Scratch-only orthographic/perspective second-host diagnostic

Not applied, built, installed, or run. Source/runtime ownership remains with root. This patch extends the existing DEBUG plain-box probe; it is not a proposed production fix.

Independent variable: set `HANGTEN_REVIEW_PLAIN_SECOND_HOST_PROJECTION=perspective` to use PerspectiveCameraComponent; omit it for OrthographicCameraComponent. `HANGTEN_REVIEW_PLAIN_SECOND_HOST=1` selects the existing purple box. Exactly one camera component is installed in init. Both modes now finish the initial camera fit before adding the root to RealityView, so this ordering is shared by the new controls. The preexisting orthographic outcome must reproduce in this new binary before making a projection inference.

The camera entity, parent hierarchy, camera position/look target, near/far clips (0.1/100), mesh, material, two lights, 68-point slot, .virtual host mode, and pose/viewport update guard are shared. No hand files or assets change. The board remains the original RealityView with its baseline camera contract. Semantic identity, ARView, explicit board virtual, and visibility probes are all OFF.

Perspective framing uses the eight analytical box corners transformed by the unchanged camera matrix. Let a be viewport aspect and d=-z the positive corner depth. Set vertical FOV to 2 atan(1.08 max(max(abs(y),abs(x)/a)/d)). This is fixed for a fixed viewport and the static box: no timer, mode, scene identity or screenshot input affects it. The existing pose/viewport guard recomputes the same value when pose alone changes. Orthographic keeps its original formula and values. FOV is finalized before initial attachment.

Residual difference is intentional and unavoidable: perspective varies apparent size with corner depth and has converging rays; orthographic does not. This fits analytic projected bounds with the same 8% margin, not exact pixel equality. `analytic-framing.json` documents depths and illustrative aspect values, not a measurement of the app. Actual viewport/FOV/scale and transform are recorded for comparison. The depth variation is small relative to camera distance but cannot be claimed zero. Do not alter box geometry to compensate.

Logging adds no tasks or timers. The existing bounded recorder and its 1 Hz/120-s board sampler retain weak references to the box root/camera after second-host make. All board sample/semantic records include actual Entity.scene identities, entity IDs, active state, camera component presence and projection parameters for board and box. Box lifecycle has its own UUID; make, guarded update and disappear append sparse records into the same newline-complete JSONL. Disappear clears registration only if its token matches; references do not own scene lifetime. Before attachment the first update intentionally records scene=nil. A scene ID is a live object identity, not an SDK renderer or GPU camera identity.

Proposed bounded same-binary sequence (not executed): O / P / OFF / OFF / P / O. O means plain box + orthographic; P means identical plain box + perspective; OFF means existing suppression gate with no second host, and both plain-box gates absent. Each launch gets a unique owner-qualified run name and an explicit review-environment allowlist. Clear all unrelated experiment variables rather than inherit ambient settings. Do not switch projection during a live host lifetime.

For each launch: use the unchanged real Evo research.max-hangs landscape workout; capture first active, settled following rest, and next active after the actual Skip button. Preserve capture start/end wall clocks, complete trace, exact screenshot hashes, and raw command results. Inspect each critical whole image individually. Success requires visible board and expected red/blue/red in all three phases, not CPU colors alone. Also require the purple box to be visible in O/P, exactly one corresponding camera component, unchanged camera transform/clips, distinct board/box scene memberships if that is what the API reports, and stable board scene/root/entity IDs across phases. OFF has no registered box. Preserve inconclusive runs and failures without replacement.

If O reproduces, P passes twice, and OFF passes twice, projection-specific interaction is supported but framework internals remain unproven. If both O/P fail while OFF passes, orthographic camera is not required. If fresh O does not reproduce or identities/layout differ, stop and report inconclusive; do not claim a fix. No production changes, new simulator resources, or cleanup actions are part of this proposal.
