# Standalone board diagnostic — scratch only

No source application, build, launch or device access has occurred. Root retains source/runtime ownership until the packaging freeze and explicit gate. Base patch touches only reserved RootView, BoardModelView and BoardModelRealityTypes. Optional counter is a second patch layered on the base, separately gated at runtime. Neither is a production fix.

RootView.body chooses StandaloneBoardHighlightProbe before evaluating the normalBody property. The prior TabView body and its modifiers move byte-for-byte into normalBody; Train, Plans, History, navigation, workout, hand and plain-box view bodies are not evaluated by the standalone branch. RootView's existing state objects still exist, and HangTenApp still supplies store/environment; neither is a renderer. HangTenApp's independent hand-review gate must be absent in the launch allowlist. No HangTenApp or hand asset/source edit is proposed.

The standalone branch gets zlagboard.evo from BoardCatalog, its authored default presentation and edge-20-left's position, then mounts the ordinary BoardModelSurface once. It uses its standard loader, model, camera, applySync/material path, and both edge-20-left/right IDs. No key/remount, timer, onChange writer, model-copy, camera nudge, tween, repeated write or direct material change is introduced. It disables model interaction only; this matches the nil tap callback display workflow and prevents a diagnostic gesture accidentally masking staleness.

A single enum starts at Clear. AX-addressable Active/Preview/Clear buttons set that enum once, guarded against same-state presses. It atomically derives the ID set and mode. For the primary test, wait for load and final landscape layout, then physically press Active, hold/capture; Preview, hold/capture; Active, hold/capture. Hold each state at least 3 seconds and capture a second image 2 seconds later if needed within the fixed first-run protocol. Do not press redundant controls, change orientation, pause, seek or orbit between phases. Clear is a separately available diagnostic state, not part of the primary three-phase decision. Root must inspect each full screenshot independently with SHA and visible state label.

Viewport: retained workout AX evidence reports 210 x 36 points in projection-off-a-landscape/active-settled-ax.json (boardModel.3d). AX frames may round and are not proof of internal GeometryReader dimensions. The patch therefore records exact size passed into RealityView make/update and samples it from the existing recorder. After build, obtain one same-binary normal-workout viewport record before launching the standalone harness; freeze those width/height values in HANGTEN_REVIEW_STANDALONE_WIDTH/HEIGHT. If that preflight is not authorized, 210x36 is an explicitly provisional AX-derived default and the result cannot be called exact viewport parity. No pixel measurement is used. Do not tune viewport after observing colors. The orientation request occurs once on appear; phase testing waits until stable orientation and viewport are recorded.

Logging: same newline JSONL recorder, bounded existing 1 Hz / 120-second sampler. Sparse make/sample and button events include UIApplication state, UIWindowScene activation/session/identity/orientation, app windows' visibility/alpha/key status/bounds and a read-only count of UIView runtime class names containing Reality or ARView. This class census is a diagnostic heuristic, not a count of GPU contexts. Together with the structurally exclusive branch, zero second-host records, one board make/scene lifecycle and stable actual Entity.scene IDs, it tests whether an unexpected extra renderer remains. Existing entity enabled/active, camera/component, material RGBA and identities are retained. If another host or board scene is observed, report isolation failure, not standalone color results.

The census reads state only, but any instrumentation can perturb timing. It adds no subscriptions, state observations or frame writes in the initial run. Avoid deriving causal success from a single instrumented result. The normal-body move is structurally reviewed as identical content, not claimed performance-neutral by construction.

Optional SceneEvents.Update patch: introduce a separately gated subscription only when BOTH standalone and HANGTEN_REVIEW_SCENE_UPDATE_COUNTER=1. Initial run leaves the latter absent. A lock-protected nonobservable in-memory UInt64 increments per event; no per-frame file writes, @State changes, material/camera changes or actor tasks. The existing 1 Hz sampler reads the count. Subscription/counter are keyed by scene lifecycle plus view UUID, cancelled on disappearance or sampler completion at120s. Callback weakly references the counter; no scene/entity ownership is added. The public subscription can itself affect scheduling; if OFF fails and ON passes, that is a diagnostic effect, not a production remedy. SceneEvents.Update counts are not proof of presented frames.

Proposed runtime gate after source review: apply base plus optional counter once, build/install with existing resource ownership, verify five executable and twelve package hashes. Clear inherited SIMCTL_CHILD_HANGTEN_REVIEW_* and launch an exact allowlist: STANDALONE_BOARD=1, HIGHLIGHT_DIAGNOSTIC=1, owner-qualified DIAGNOSTIC_RUN, LANDSCAPE=1 and frozen WIDTH/HEIGHT. No deep link and no plan/board-picker launch. All semantic identity, visibility, ARView, board virtual, telephoto, hand review, plain box and hand-suppression gates absent. Subscription flag absent for first run. Record launch environment, AX buttons, each action timestamp, screenshots and complete trace before/after all phases; reject brackets with wrong mode, scene or missing samples. Only if root finds a reason, repeat one fresh launch with identical environment plus UPDATE_COUNTER=1. No source rebuild or additional variable between those two runs. Stop and hand back evidence; no speculative correction follows automatically.

Interpretation: a standalone failure with correct CPU samples narrows investigation below workout/TabView/multiple-host presentation. A standalone pass does not alone prove any one removed ancestor caused the defect; it warrants an ancestry reintroduction plan. Foreground/inactive/window-hidden discrepancies must be evaluated before rendering conclusions. Keep all partial runs and raw errors, and preserve existing accepted CAD bytes.
