# Scripted standalone board diagnostic — revised, scratch only

No source application, build, launch or device access. Prior manual proposal is preserved under v1-manual-unapplied. Root reviews before any application. Base patch touches only reserved RootView, BoardModelView and BoardModelRealityTypes; optional counter is layered separately so both can be built once with the counter gate initially absent. Neither is a production fix.

RootView.body selects StandaloneBoardHighlightProbe before evaluating normalBody. The original TabView and all its modifiers move unchanged into normalBody. The standalone branch therefore does not evaluate Train/Plans/History/navigation/workout/hands/plain-box bodies. Existing RootView state objects and HangTenApp store/environment remain; no app entry-point or hand-file changes. All other review flags, including HangTenApp's hand-review flag, must be absent. Read-only UIKit host-class census is supporting evidence; source branch exclusion, one loaded board scene and zero second-host records establish the intended isolation. Do not describe class-name matching alone as proof of no GPU context.

Mount the ordinary BoardModelSurface from BoardCatalog zlagboard.evo once, with its existing presentation/position, loader, camera, applySync and materials. Start neutral: no contact IDs. The same enum derives edge-20-left/right and active/preview mode. Stable host, fixed viewport, no .id change, direct material writer, camera/transform nudge, animation or hand slot. Active/Preview/Clear AX buttons remain available but UNUSED for primary runs.

Timing: a single cancellable .task waits up to20s for model root attachment, active camera, valid viewport, foreground application and at least1s unchanged viewport. Readiness is an in-memory check at100ms with no I/O, render mutation or SwiftUI writes. Once ready, publish an absolute uptime/epoch schedule whose first phase starts2s later. Script clear → active → preview → active → preview at8s intervals, one enum assignment per changed phase. Each state lasts8s. A requested-state event precedes the enum assignment. Existing highlight-before/highlight-after log actual scene/material mutation times independently; do not equate requested time with mutation or displayed presentation.

NO existing 1 Hz sampler runs in standalone mode. No AX polling, touch, gesture, orientation change, deep link, pause or other UI input during the40s measurement. Orientation request occurs only on initial appearance; wait for stable viewport before schedule. Sparse CPU/app snapshots are predetermined at each phase +0.15,+0.85,+1.75,+2.85,+3.75,+6.85,+7.75 seconds. Host screenshots target +0.25,+1,+3,+7 and retain actual process start/end epochs; choose trace snapshots truly bracketing those actual intervals, not theoretical times. Missing brackets or overlapping next-phase changes remain explicit limitations. File I/O occurs only at semantic/lifecycle events and these sparse brackets, never per frame.

Host capture protocol: launch once via exact UUID with a fresh diagnostic run folder. Read JSONL until standalone-schedule (bounded readiness wait) without touching UI, then stop polling and use recorded baseEpoch/phaseSeconds for all20 scheduled whole screenshots. After final capture, copy complete JSONL once. Use simctl screenshots only during measurement; record start/end times and failures. Run no AX request until the scripted sequence is finished. If the schedule is already late, app inactive, board unavailable or layout changes, preserve failure and stop; do not rebase silently. Judge each of four color phases through its final settled +7 image, opening critical images separately; CPU or request state is not a visual verdict.

Viewport: retained workout AX boardModel.3d frame is210x36pt, SHA-bound in viewport-source.json; AX may round. Exact parity requires a separately approved, same-binary normal-workout metadata capture before the standalone series, then freezing WIDTH/HEIGHT env values. Without that preflight, use fixed210x36 as a CONTROLLED TEST ADAPTATION and expressly do not claim exact workout viewport match. Do not tune dimensions after viewing results. The manifest presentation/board camera remains unchanged. Configure finite positive dimensions and confirm actual viewport equals configured size in the schedule.

Census: sparse records include UIApplication state, UIWindowScene session/activation/orientation, app-window IDs/visibility/alpha/key status/bounds, and read-only renderer-like UIView class counts. Existing logs retain actual board Entity.scene IDs, root/camera/entities, active/enabled states, projection component, transforms and RGBA. One selected scene/root/camera and stable viewUUID are required. No second host should be registered. Reading UIKit trees and writing logs may perturb scheduling; this instrumentation is not a fix and is held equal in A/B.

Optional counter patch: only if HANGTEN_REVIEW_SCENE_UPDATE_COUNTER=1 when standaloneSchedule runs, subscribe to that root's public SceneEvents.Update. Callback only increments a lock-protected, nonobservable UInt64. No @State, file writes, material/camera changes, actor dispatch or timer per event. Sparse snapshots read the counter. Cancellation occurs after the final snapshot, task cancellation (defer), or matching scene/view disappearance. Callback weakly references counter and adds no entity ownership. Subscription may itself change scheduling; a difference between A and B demonstrates an observation effect, not a remedy. Events are not proof of displayed frames.

First A must be valid before continuing; root may stop once evidence suffices. All inherited SIMCTL_CHILD_HANGTEN_REVIEW_* stripped. Allow only STANDALONE_BOARD=1, HIGHLIGHT_DIAGNOSTIC=1, owner-qualified DIAGNOSTIC_RUN, LANDSCAPE=1, frozen WIDTH/HEIGHT, and B-only counter. No plan/workout URL. Verify five executable files and twelve package hashes after the single build/install. No renderer/backend rewrite, transient geometry changes, or additional experiment automatically follows.
