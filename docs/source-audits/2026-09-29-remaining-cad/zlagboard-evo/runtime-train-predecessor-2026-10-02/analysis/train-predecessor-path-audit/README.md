# Train predecessor path audit

The only direct board map in the normal initial Train body is `TrainView.selectedBoardCard` at lines139–142. The picker (including display-only cards), board detail, plan-detail preview, custom editor and free-workout flows can create hosts, but require their own destinations/sheets. The retained no-input launch environment activates neither review-plan/detail/picker nor another tab. Plans' root and History do not directly embed board maps. SwiftUI destination/tab laziness is not used as proof of lifetime absence.

Existing normal traces record three/two/two board makes in O1/P1/strictOFF; reports classify two/one/one predecessors. Their initial metadata is identically Evo/primary/empty IDs/displayOnly=false, which also fits a preactive workout map. There is no origin tag, so those records do not uniquely attribute every prior host to Train. Surface disappearance clears its loaded result; recreation may load another scene. The resource cache does not reuse the mutable scene: the loader constructs a fresh one per successful load. Counted predecessors therefore need not imply another tab or picker.

A Train-only gate must prevent the exact card's BoardMapView construction, preserving surrounding layout, and leave workout maps active. Hidden/transparent views are insufficient. To verify isolation without per-body logs, propagate a static DEBUG origin tag from that lexical callsite into one-time load/scene/make lifecycle events, using the existing input event for metadata where possible. Require zero Train-tagged construction/make records under the gate, and account for every remaining scene/view token as an expected workout host, including portrait-to-landscape replacements and canceled loads. Unexplained tokens fail the gate. A shared constructor/loader event closes the current gap where a scene can load then cancel before any host make. No per-tick/body event or new sampler is needed.

Fresh-process exact launch flags and deep-link history must exclude the other review routes. Existing sparse UIKit census still checks actual matching ARView/root/camera, but is not a lifetime registry. Without origin/construction instrumentation the honest conclusion is only no additional observed host makes, not guaranteed absence of every unintended predecessor. All recommendations are prospective; no source or runtime changes occurred. `audit.json` and hash-bound source excerpts give exact paths; `existing-lifecycle-observations.json` extracts only frozen traces.
