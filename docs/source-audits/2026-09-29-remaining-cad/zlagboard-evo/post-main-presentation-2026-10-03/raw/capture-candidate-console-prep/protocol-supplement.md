This prospective revision redirects app stdout/stderr in BOTH control and action (and any separately authorized reversal) to absolute paths inside that run’s exclusive owner-scoped output directory. It uses public nonblocking simctl launch --stdout=<path> and --stderr=<path>; it does not use --console or --console-pty. The simctl command’s own stdout remains separately retained for exact app PID registration.

The purpose is to retain existing Main helper print-match receipts. No new diagnostic flag, callback, sampler, app code, or in-run log polling is introduced. Routine, passive screenshot schedule, setup, release hashes, allowed flags, and exact app/child cleanup stay identical to the prior candidate helper. Both arms share this output observation change. The first baseline did not redirect app streams, so observation conditions are not identical to that baseline; no timing neutrality or causal equivalence is assumed.

Raw app.stdout/app.stderr are retained unmodified in the run directory, including failures if created. Absence of a receipt does not by itself prove the helper did not run. Interpretation must check source/binary identity, helper predicate and run completion separately. Logs are frozen only after exact app termination is verified. This preparation does not authorize runtime; root supplies the candidate source/parity/binary release.
