# Frame refinement after first comparison

First comparison: unchanged live board has stale Rest and following-Hang colors. Explicit completed frames show phase-correct colors in every visible selected frame, but fail appearance and one transition has no board. Full first candidate remains FAIL, preserved.

The next candidate adds a runtime camera-relative white key light with shadows and a lower-power fill. This is display lighting, not manufacturer evidence or a change to CAD/material metadata. Whole views must establish useful cavity relief and matching wood finish.

A bounded two-frame cache keeps completed active and preview outputs for the current contacts, position, viewport and orbit. After a requested image finishes, the alternate mode is prepared once. Cached output is selected using the current semantic input, before onChange delivery, so a mode switch cannot show the old color or deliberately empty the slot. A proportionally resized completed frame can remain visible during aspect-preserving layout animation while fresh resolution renders. Other contacts/positions/aspects cannot substitute. GPU work remains serialized and idle boards have no redraw loop.

The first focused cache test uses a non-rendering stub to establish expected failures before implementation. GPU completion lifetime remains separate; no resources are freed while the GPU can use them. A thrown submission clears its unsubmitted frame. No fabricated cancellation or frame-completion guarantee.

Require whole-image active/Rest/following-active validation and actual hand cues; then gesture, clearing and Pro checks and clean production selection before adoption. No human geometry acceptance changes.
