Scratch design only: separate weak observation from retained-model detachment

Question: does the structural-removal comparison behave differently when both arms omit the existing intentional model/lease retention and explicit detach action? This is a diagnostic comparison, not a production candidate. Current reversal outcome remains a gate for whether to run anything further.

Current coupling: boardDetachTrial gates Train marker/navigation/clear-slot behavior, host registration/census, and TrialHost's unconditional strong model. The readiness helper additionally requires modelRetainedForTrial=true. Simply removing the trial flag would therefore remove observation/readiness and disable structural removal. Current sampler already captures scene weakly and is canceled at disappear; no sampler change is needed.

Smallest compatible separation: add one DEBUG launch-only observation flag HANGTEN_REVIEW_BOARD_HOST_OBSERVATION. A derived observesBoardHosts gate is true for this flag OR the existing boardDetachTrial, preserving old launches. Use that derived gate only for existing tagging/navigation, registration, observations and structural-removal eligibility. Keep boardDetachTrial as the legacy intentional-retention selector and its existing action flag as detach selector. Existing detach guards remain exact.

TrialHost keeps weak model/root/camera fields plus an optional retainedModel populated ONLY when boardDetachTrial is true. The dictionary retains observation records and UUIDs, never models/entities/leases in the observation-only configuration. Weak parent and actual-scene fields stay weak. Capture the alive/retained status honestly; a nil wrapper/root after ordinary removal is valid observation, not a forced retention or a pass inferred from nil. Preserve weak entity references independent of the wrapper so dead-wrapper/live-entity states remain observable.

Prospective dependency check is exactly TWO arms, BOTH with structural unmount enabled. Both use identical observation, predecessor census, strict-hands OFF, normal Train startup, readiness and natural workout timing on one new binary. Arm A enables legacy intentional retention plus explicit guarded detach; arm B omits BOTH interventions. Both set UNMOUNT_TRAIN_FOR_WORKOUT=1. All other old experiments and initial Train suppression remain absent. No present/removed pairs or four-arm matrix are proposed. This compares the combined intervention; it cannot separate detach effects from retention effects. No runs are authorized.

Readiness: keep the same 20-second bound, exact Train-tagged make, actual root/camera shared parent/scene, weak liveness, current owner and no-disappear guards. Replace the unconditional retained requirement with modelAlive plus retained-state equality to the prospective launch configuration. Both require a live real Train host before openurl. Keep existing polling interval, no fixed delay or new sampler/counter.

Validation needs an explicit new checker version: distinguish record existence from live wrapper, assert retention flag false and detach flag absent in ordinary arms, preserve two constructor/make identities and workout attachment/frame gates. After ordinary removal allow wrapper/entities/old parent/scene to die naturally; report all liveness rather than require 139 alive/detached records. In intervention arms retain prior exact detachment/ownership/liveness checks. A changed absence/census gate is not retroactive validation of earlier runs.

No additional normal callbacks, body logs, timers, tasks or state mutations. Existing before/after disappearance event names can remain for compatibility but mean observation in the ordinary arm; detachRequested=false and modelRetainedForTrial=false disambiguate them. No release-build changes, source application, build, tests, device use or root-cause claim.
