# Metolius Simulator 3-D mounting-hole geometry repair

Reviewed 2026-09-22. This repair replaces the prior display-only occlusion of
`metolius.simulator-3d`'s eight source mounting-hardware openings with a
direct topological repair of the body mesh. It does not add, move, remove, or
resize any physical contact; all 31 `hold_*` contact meshes are
vertex-for-vertex unchanged.

## Background: the prior caps-based workaround

The 2026-09-16 import
([`2026-09-15-hangboard-collection-model-imports.md`](2026-09-15-hangboard-collection-model-imports.md#metolius-simulator-3-d-metoliussimulator-3d))
identified eight visible mounting-hardware openings in the supplied source
geometry. Because the display-model contract excludes mounting hardware, that
import authored a second, nonselectable body mesh,
`mounting_hardware_omission_caps_001`, with eight flat display-only caps
positioned over the openings. The caps were a camera-framing occlusion, not a
closed surface: they were separate floating geometry laid across the holes,
not a repair of `board_body_001` itself.

## What changed

`board_body_001` itself is now closed at all eight former opening locations:
each opening is patched with a surface fitted to the sampled geometry of its
immediate surrounding rim (curvature and thickness carried over from
neighboring vertices), not from manufacturer measurements, CAD data, or any
published mounting-hole specification. This is the same
`authored-display-estimate` standard used elsewhere in this catalog for
unsourced geometry: it makes the display model watertight at the display
contract's request; it is not a claim about the physical mounting hardware's
true diameter, countersink, or depth. The now-redundant
`mounting_hardware_omission_caps_001` node is removed — the body it used to
cover no longer has openings for it to hide.

No change was made to any `hold_*` contact mesh. This was independently
verified, not assumed: every one of the 31 `hold_*` meshes in the repaired
USDZ has vertex coordinates, vertex count, and polygon count byte-identical to
the corresponding mesh in the prior shipped USDZ (`3372f4d2b4...`).
`board_body_001` grew from 101,204 to 102,351 vertices and from 170,414 to
172,492 triangles, consistent with patching eight openings by adding rim-fitted
fill geometry.

## Raycast hole-oracle evidence

`Tools/HangboardModels/find_holes_raycast.py` fires a dense +Y ray grid
(0.5 mm pitch) across the board's silhouette and clusters the misses. The two
largest clusters are always the background outside the board silhouette;
anything beyond those two is a real through-opening in the scanned geometry.

Six of the eight authored caps left a real gap to the +Y raycast direction at

Only the two background clusters remain. All eight prior openings are closed
in the body mesh itself.

## Descriptor regeneration

`Tools/HangboardModels/contact_model_descriptor.py`'s `compile_descriptor`
derives every descriptor field solely from bound USDZ node vertices — it has
no path for authored or hand-edited values. The promoted
`assets/primary.model.json` was regenerated by this function and independently
re-derived for this audit by importing the promoted USDZ, extracting the exact
node vertices in the `hang-ten-board-v1` frame, and calling
`compile_descriptor` directly: the recomputed JSON is byte-identical to the
committed descriptor. `modelSHA256` in the descriptor equals the SHA-256 of
the committed `assets/primary.usdz`.

## Test changes

`Tools/HangboardPackages/tests/test_approved_board_packages.py`'s
`test_simulator_3d_models_flat_and_round_sloper_zones_separately` asserted a
two-member body-node set (`board_body_001`,
`mounting_hardware_omission_caps_001`). It now asserts the single remaining
body node, `board_body_001`. No other assertion in that test file names a
vertex count, polygon count, or node count for this package, so no other test
change was required. Before making this change, all 31 `hold_*` meshes were
confirmed topologically and positionally unchanged (above); had any
contact-bearing hold differed, this would not have been treated as a passing
repair.

`Tools/HangboardPackages/tests/test_hard_cut_audit.py`'s closed
`Tools/HangboardModels` file inventory was extended to include the new
`find_holes_raycast.py` oracle used to produce the evidence above, following
the same pattern as the existing per-board `verify_*.py` tools in that
directory.
