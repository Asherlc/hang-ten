## Issues

### Critical

### Important

1. **Descriptor center validation does not use the compiler/parser's nine-decimal rounding rule.** `roundedToNinePlaces` scales by `1e9` and calls Swift's default `.rounded()`, whose midpoint behavior is away from zero, while the Task 4 parser and compiler contract use Python `round(value, 9)`. For example, a valid normalized AABB from `0.1` to `0.100000023` has the canonical Python-derived center `0.100000011`, but this helper derives `0.100000012` and rejects the descriptor. Thus a descriptor accepted/generated by the Python side can fail in the app solely at a rounding tie. The same scaling implementation can also overflow while checking otherwise finite, already-nine-decimal large coordinates. [HangTen/Models/BoardPackageStore.swift:1547](../../../HangTen/Models/BoardPackageStore.swift#L1547), [HangTen/Models/BoardPackageStore.swift:1589](../../../HangTen/Models/BoardPackageStore.swift#L1589), [Tools/HangboardPackages/src/hangboard_packages/board_catalog.py:1309](../../../Tools/HangboardPackages/src/hangboard_packages/board_catalog.py#L1309)

2. **`BoardHold` did not become a logical-only value as required.** It still publicly stores legacy `geometry`, cached `frame`, and `presentationID`; the v2 initializer fills those fields with empty/zero sentinels instead of removing presentation-owned spatial state. This permits v2 consumers to read plausible-looking but false zero/empty values and does not force them onto `resolvedFrame(in:)` or typed media. It also diverges from the Task 4 representation, where only the private legacy-v1 hold subtype owns geometry and presentation identity. [HangTen/Models/TrainingModels.swift:596](../../../HangTen/Models/TrainingModels.swift#L596), [HangTen/Models/TrainingModels.swift:708](../../../HangTen/Models/TrainingModels.swift#L708)

3. **Swift accepts noncanonical descriptor hold ordering that the strict Python v2 parser rejects.** Descriptor `holds` is decoded directly into a Swift dictionary, discarding JSON member order, and validation subsequently checks only its key set while iterating the logical IDs in sorted order. The Task 4 parser explicitly requires descriptor hold members to be sorted by `holdID`, so the two package loaders disagree on accepted descriptor bytes and Swift does not enforce the descriptor's deterministic sorted-output contract. [HangTen/Models/BoardPackageStore.swift:1533](../../../HangTen/Models/BoardPackageStore.swift#L1533), [HangTen/Models/BoardPackageStore.swift:1817](../../../HangTen/Models/BoardPackageStore.swift#L1817), [Tools/HangboardPackages/src/hangboard_packages/board_catalog.py:1276](../../../Tools/HangboardPackages/src/hangboard_packages/board_catalog.py#L1276)
